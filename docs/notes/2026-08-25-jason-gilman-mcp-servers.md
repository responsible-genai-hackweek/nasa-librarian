## Notes

### Who
Jason Gilman worked on **NASA CMR**. Helped build **ChatGSFC** — an agentic tool for
NASA internal use, **9,000+ internal users**.

### Adjacent effort
**Element 84** is building a **general-purpose geospatial agentic tool**.

### MCP and context

The MCP server **contributes to context**. Primitives again: tool, resource, prompt.
Tool calls are generated by the LLM and read back on subsequent calls. **Responses can
dominate the context.**

### Story time — the risk-analysis challenge

Hundreds of Excel and PDF files. The goal was to use the data inside those documents to
understand risk across a project. Many MCP servers connected to a single agent —
and the context window **exploded**.

## What this means for us

Second speaker in a row on this — Joe's version was *"don't ask for 10 GB via MCP."*
Jason adds a distinct failure mode: it is not only responses. **Every connected
server's tool definitions sit in context before anything is asked.**

### Measured: what being a client of `nasa/earthdata-mcp` costs

Pulled from the live server, 2026-08-25 (chars, and tokens at ~4 chars/token):

| | chars | ~tokens |
|---|---|---|
| `instructions` block | 19,249 | **4,812** |
| 7 tool descriptions | 10,277 | 2,569 |
| 7 tool input schemas | 14,168 | 3,542 |
| **Total** | **43,694** | **~10,900** |

**~11k tokens before a single query.** Joe's `/mcp` showed eight servers connected at
once; at this scale that is on the order of 80–90k tokens of pure definitions.

Per tool, the two we actually need are the expensive ones:

| tool | ~tokens |
|---|---|
| `get_collections` | 2,129 |
| `get_granules` | 1,643 |
| `get_tools` | 622 |
| `get_services` | 563 |
| `get_variables` | 421 |
| `get_keywords` | 351 |
| `get_citations` | 381 |

### Three consequences

1. **Connect selectively.** The librarian needs `get_keywords`, `get_collections`,
   `get_granules` and `get_variables` — about 4.5k tokens of the 6.1k in tool
   definitions. `get_tools`, `get_services` and `get_citations` are dead weight for our
   flow. If we control the client, expose a subset.
2. **The readiness record's budget is what's left.** The librarian holds five to ten
   records at once while ranking, on top of ~11k of definitions and paginated CMR
   responses. Reinforces: compact verdict, not metadata dump.
3. **A quantified version of the scaling argument.** NASA's `instructions` block is
   already **4,812 tokens** — and it encodes exactly *one* dataset-specific caveat (the
   HLS Fmask quirk). Every DAAC quirk added makes it longer, and every agent using the
   server pays for all of them on every request, whether or not the query touches that
   dataset. **A record is fetched only for the datasets under consideration. A prompt
   is paid for always.** That is the architectural case for the record, in tokens.
