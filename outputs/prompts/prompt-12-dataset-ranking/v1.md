# Prompt-12: Dataset Ranking Report (Version 1)

## Purpose

Transform an enriched user story into a **Dataset Ranking Report** — a structured analysis of candidate datasets ranked by fitness (not relevance) to answer the user's question at their stated scale.

## Input

An enriched user story with:
- Six slots (unit of analysis, time window, cadence, variable meaning, effect size, latency)
- Gotchas & traps (where naive approaches fail)
- Dataset suitability criteria (would/wouldn't work)

## Your Task

You have access to `earthdata-mcp` tools. Your job is to:

1. **Parse the enriched story** — extract the constraints
2. **Query earthdata-mcp** to find candidate datasets
3. **Rank by fitness** — not relevance. Fitness = (dataset meets spec) AND (avoids gotchas)
4. **Analyze each candidate** — does it fit? Which gotchas does it hit or avoid? Quality-of-fit score
5. **Refuse when appropriate** — if all candidates fail an axis, say so clearly
6. **Produce a structured report** with metadata, ranked candidates, and recommendations

## Instructions

### Step 1: Extract Constraints

From the enriched story, state:
- **Unit of Analysis:** What scale? (e.g., 1–10 km patches)
- **Spatial Resolution Required (m):** Minimum pixel size
- **Time Window:** How many years of data?
- **Temporal Cadence:** How often? (daily, weekly, annual?)
- **Latency Tolerance:** How fast must the answer come? (hours, days, weeks?)
- **Variables:** What to measure? (e.g., vegetation index + subsidence)

### Step 2: Search earthdata-mcp

Use `get_collections()` to search for datasets matching:
- The variables from Step 1
- The region/topic from the enriched story
- Time span and cadence

**Search Strategy:**
- Start with most specific variable (e.g., "InSAR subsidence" before "vegetation")
- Try multiple search terms (e.g., "Landsat", "Sentinel-2", "SMAP")
- For each collection returned, note: resolution, time span, cadence, latency

### Step 3: Evaluate Each Candidate

For EACH dataset returned:

1. **Specification Fit:**
   ```
   Resolution:    [actual] m vs [required] m → FITS / TOO COARSE / PARTIAL
   Time Span:     [actual] vs [required] years → FITS / TOO SHORT
   Cadence:       [actual] vs [required] → FITS / TOO SPARSE
   Latency:       [actual lag] vs [required] → FITS / TOO SLOW
   Variables:     [what it measures] vs [what's needed] → FITS / MISMATCH
   ```

2. **Gotcha Analysis:**
   - **From the story's "Trap for naive picker":** Does this dataset hit that trap?
   - **Regional caveats:** Does this dataset fail in this region?
   - **Measurement artifacts:** Does it have known failure modes?
   - **Scale trap:** Can it resolve the unit of analysis?

3. **Quality-of-Fit Score:**
   - **HIGH:** Fits all specs, avoids all gotchas, explicitly in "Would Work" list
   - **MEDIUM:** Fits most specs, might hit a gotcha
   - **LOW:** Fits some specs but fails critical axis, or in "Wouldn't Work" list

### Step 4: Rank & Refuse

**Rank all candidates by fitness (high → medium → low):**
- High-fitness candidates first
- Medium candidates with caveats noted
- Low-fitness candidates with clear explanation of why

**Refuse when appropriate:**
- If ALL candidates fail an axis (e.g., all too coarse), state it clearly
- Propose alternatives (drone, models, ground sensors) if satellite won't work
